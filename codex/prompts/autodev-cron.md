Scheduled autonomous development run for this repo (cron cadence — assume ~25 min of useful work). Follow the Agentic System section of AGENTS.md. Off-hands: the owner is away; park owner-only decisions with recommendations and never wait.

0. **Environment.** If a RUNNER-DRIVEN context header is present, the runner already holds the run lock and prepared a clean checkout at the default tip — SKIP locking and syncing and cut your feature branch right here. Otherwise (interactive invocation): overlap-guard with a lock at `/tmp/autodev-<slug>.lock` (NOT inside `.git`, which may be read-only), `git fetch`, and start clean from the default branch — never build on a dirty tree.
1. **Decisions first:** read the pending queue in `~/.claude/decisions/<project>.md`. Apply anything the owner resolved (log D-ids, resume what it unblocks). If every remaining work item is decision-blocked, exit with a state note.
2. **Resume before starting:** an in-flight branch/PR from a previous run (unfinished stages, reviewer findings, red CI) gets finished before any new item.
3. **Then take ONE item:** top ready item from the tracker chain (Jira → plandb → BACKLOG.md), sized to complete within the run; if the top item is too big, split it in the tracker and take the first slice. First run ever on a repo: bootstrap per /autodev instead (assessment + PM-drafted backlog into the decision queue; quality work only until approved). **A valid item produces a real code/test/config change.** Reconciling, annotating, or "recording evidence" in a tracker/status/docs-tracking file is NOT a work item. If the only remaining action is tracker bookkeeping, or every backlog item is blocked / owner-gated / needs a non-sandbox environment → do NOT invent work and do NOT open a PR: append an `idle` / `blocked` Work Log note listing the specific blockers (as parked decisions) and STOP.
4. **Full pipeline** → green marker → push → PR **targeting the base branch named in the context header** (default `staging` — NEVER open a PR against `main`). The PR diff MUST contain a real code/test/config change — **NEVER open a PR whose only changed files are tracker/status/docs-tracking files** (e.g. a `launch-task-tracker.md`); update the tracker as part of a real change, never as the whole change. A promote-to-main / release-to-main task is owner-only: park it, do not do it. Tracker reference in title + body. One item, one PR, never merge.
5. **Hand off:** end with a state note (done / in-flight / parked) appended as a `## Work Log` line in `~/.claude/decisions/<project>.md` (`| date | what | PR or trail | track/model |`) — this feeds the owner's daily digest — plus enough state on the tracker item for the next run to resume cleanly.
